# 开发规范

## 本地开始

安装、配置和启动步骤见 [README](../README.md#本地开始)。真实凭据只放在受控环境中，不提交到仓库。

## 日常检查

| 命令 | 用途 |
|---|---|
| make test | 运行全部单元与契约测试 |
| make check | Python 编译与测试，以及 JavaScript 语法和前端测试 |
| make run | 本地启动 FastAPI |

新增或改变行为时，必须同时新增或更新 tests/ 下的测试；测试源码是仓库的一部分，不能放入 .gitignore。

## 分支与提交

1. 从最新 main 创建短期分支，推荐前缀 feature/、fix/、chore/ 或 docs/。
2. 一个分支只解决一个可说明的问题；不混入无关格式化或历史文件清理。
3. 合入 main 前运行 make check，并更新 README 或相关运维文档。

## 版本号

服务版本采用语义化版本：`MAJOR.MINOR.PATCH`，发布 tag 使用 `v` 前缀，例如 `v0.2.0`。

| 变化类型 | 版本变化 | 本项目示例 |
|---|---|---|
| 不兼容变更 | 升 `MAJOR` | 删除或改变已有 HTTP/MCP 参数、返回字段或鉴权方式。 |
| 向后兼容的新能力 | 升 `MINOR` | 新增可选查询能力、新增 MCP tool、增加不影响旧调用方的返回字段。 |
| 向后兼容的修复 | 升 `PATCH` | 修复 DSL、结果映射、鉴权或部署缺陷，且不改变既有契约。 |
| 仅文档 | 保持版本号 | 提交 Git 即可；不需要重启服务。 |
| 仅索引 alias 切换且接口行为不变 | 保持版本号 | 按索引维护手册验证数据与查询结果，并准备回滚。 |
| 索引切换导致可观察查询语义或结果契约改变 | 通常升 `MINOR`，不兼容时升 `MAJOR` | 例如 IPC 查询语义调整导致调用方需要修改用法。 |

在 `0.x` 阶段，仍按上述规则管理；如果变更不兼容，可以升 `0.MINOR.0`。不要用日期、服务器目录名或物理索引名代替服务版本。


## 部署与索引

服务部署和回滚见[部署手册](ops/deployment_runbook.md)；读别名、数据兼容与索引回滚见[索引切换手册](ops/index_cutover.md)。两类操作分别验证和记录。

## 合并前检查

合并改动前检查以下项目：

1. 代码和测试均提交到 Git。
2. make check 通过。
3. 文档反映当前行为，而不是计划或历史状态。
4. 涉及配置、部署或索引时，已写明验证与回滚方式。

## 文档维护规则

每类事实只维护一处：README 负责入门和架构，API 文档负责请求、查询语法与返回契约，向量文档负责向量执行与排序管道，运维手册负责操作步骤。完整入口见[文档索引](README.md)。

- 修改接口、配置或脚本时同步更新对应说明；不在多个文件复制易变化的数值。
- `make check` 包含本地 Markdown 链接/锚点、JSON 代码块和 HTTP 搜索示例检查；也可使用 `.venv/bin/python scripts/check_docs.py` 单独执行。语义与部署配置需对照代码及实际环境检查。
- 临时测试结果、备份、凭据和运行数据不得提交。
- `scripts/` 只保留仍有效的工具；映射器行为由 `tests/test_search_result_mapper.py`、`tests/test_detail_mapper.py` 和 `tests/test_patenthub_adapter.py` 统一验证。
- 对线上发起检索的 smoke/benchmark 会产生真实负载；运行参数说明见 API 和对应工具目录。管理员 runtime smoke 会应用并回滚参数，属于写操作，不能混入只读检查。
